# Mobile Money Account Takeover & Transaction Abuse Analytics
### Milestone 2 - Working Prototype (Repository Snapshot)

Members: 222073470 (Member A) · 201086263 (Member B)

This repository is the **Milestone 2 code/prototype bundle** accompanying the
Project Implementation Plan (PDF). It implements an end-to-end, reproducible,
**synthetic-data-only** pipeline from data generation through to an
analyst-facing risk dashboard.

> No real customer, transaction, or device data is used anywhere in this
> repository. All records are generated by `src/generate_data.py` with a
> fixed random seed for reproducibility.

## Quick start

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
bash run_all.sh
```

This regenerates all data, runs every analytical module, runs the test
suite, and leaves the analyst prototype ready at `prototype/dashboard.html`
(open directly in a browser — no server required).

## Repository structure

```
data/                 synthetic CSV extracts (generated, not committed as "real" data)
src/
  generate_data.py    synthetic auth / transaction / device / support-ticket generator
  eda_features.py      cleaning, quality checks, data dictionary, account-level features, baseline charts
  models.py             supervised classifier (Random Forest) + unsupervised anomaly detector (Isolation Forest)
  text_mining.py         TF-IDF classifier + keyword/indicator extraction on support tickets
  simulation.py           3 injected scenarios incl. 1 negative control, scored by the trained pipeline
  predictive_risk.py       rolling early-warning score trend + adversarial/robustness test-case plan
outputs/               all preliminary result artefacts (json/csv/png) produced by the modules above
prototype/
  dashboard.html        self-contained analyst-facing prototype (data embedded, no server needed)
  dashboard_data.json    the same bundle, as raw JSON, for reference
tests/
  test_pipeline.py       pytest suite covering data integrity + model sanity checks
run_all.sh              runs the full pipeline + tests in one command
requirements.txt        pinned minimum package versions
```

## Preliminary results summary (see `outputs/*.json` for full detail)

- Supervised classifier (Random Forest): precision 1.00, recall 0.86, PR-AUC 1.00 on held-out synthetic test accounts.
- Anomaly detector (Isolation Forest, top 5%): precision-at-top-N = 1.00 against synthetic ground truth.
- Text classifier (TF-IDF + Logistic Regression): macro F1 = 1.00 on synthetic ticket categories.
- Simulation: SIM-swap wave and credential-stuffing scenarios both trigger 100% alert rate; the
  legitimate-travel negative control triggers a 76% alert rate at the default 0.5 threshold — see
  **Known issues** below.

These metrics are **inflated by the cleanliness of the synthetic generator** (classes are, by
construction, more separable than real fraud data would be). They demonstrate the pipeline
is wired correctly end-to-end; they are not a claim of real-world performance.

## Known issues / defects

1. **Elevated false-positive rate on legitimate travel.** The negative-control simulation
   (`legit_travel`) alerts on 76% of simulated legitimate-travel accounts at the 0.5 threshold —
   too high for production use. Root cause: `geo_dispersion` and `mean_mfa` are not yet enough to
   separate genuine travel from account takeover on their own.
2. **Synthetic-data separability inflates metrics.** Precision/recall/F1/PR-AUC are near-ceiling
   because the generator creates cleanly separated classes; real data will be noisier.
3. **No sequence/velocity features yet.** Detection of "low-and-slow" patterns (see `ADV-1` in
   `predictive_risk.py`) is not yet implemented.
4. **Dashboard is static/offline.** It reads an embedded data snapshot rather than a live
   pipeline; no authentication or role-based access control implemented (out of scope per Charter).
